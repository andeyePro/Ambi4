# UI review — one interaction model, nested progressive complexity

Date: 2026-10-03. Repo state: `dev` at e59b7ef (v0.0.206). Method: code reading
only; no browser was available, so every control count is from markup and
builder functions, not from a rendered page. Line numbers are
`src/pages/index.astro` unless another file is named.

The yardstick is the owner's standing rule (CLAUDE.md, 2026-10-03): *learn one
way to interact and you know how everything works; staying basic, everything
looks simple and sounds good; drilling down reaches every nuance; pro speed
comes from keybindings, pins, favourites and saved layouts, not from putting
every control on the surface.*

Short verdict: the app already owns a good model in three places — the knob
(`src/scripts/knob.js`), the rule primitive (`src/scripts/rule-control.js`:
Now / Chance / Pool with "more"), and `setupPopover` (17550). The trouble is
that most surfaces built before v0.0.196 do not use them, so the same job is
done three or four different ways, and the two biggest surfaces (the Create
popover and the voice editor) put every layer on screen at once.

## 2. Inconsistencies — the same job done more than one way

### 2.1 Setting a value

- **Knob** almost everywhere (knob.js). **Native range slider** in three live
  (non-fallback) places: arp Octaves and Gate (10343-10395, `arpRange`, never
  tries `knobApi`), structure-block intensity (14711). Every other
  `type = 'range'` (5056, 6404, 6980, 7100, 7231, 7344, 7605, 7677, 9617,
  10565, 12851) is the knob-failed fallback and is fine.
- **Number input** for weights: sequencer tab Weight 0-100 step 0.5 (8193),
  blend weights (14338), kit pool weights (9639), block bars. Same concept
  (a weight) at two scales.
- **Stepped knob vs select** for an enumeration: Filter Type is a stepped knob
  (12010); Arp Pattern/Rate, groove Feel/Lengths/Anchor/Offbeat (6711-6743),
  drift shape (7147) are selects.

### 2.2 Choosing one of N

- Native **select** (genre, voice, root, scale, metre, structure, When).
- **Segmented radios** (track state 4232, Poly/Mono 7024, Universal/Per
  instrument 7461, Auto/Manual 8128 and 10270, Shuffle/In order 8208, kit
  tabs 12325).
- **Cycle button**: the track lamp (800-808) cycles Off/Auto/On — the very
  same state the editor shows as three radios (12254). Two widgets, one value,
  on screen together when the editor is open.
- **Actions hidden inside selects**: "Pool of voices…" in every voice select
  (4361), "Favourites…" / "Surprise me" in the genre select (16594-16600),
  "Custom…" in time signature (866) and structure. A select that sometimes
  opens a dialog is a different interaction from one that sets a value.

And the knob's own documentation contradicts itself: the knob.js header

and tour step 3 (19750) tells users "Double-click restores the default". The
scope legend uses double-click to solo (tour text ~19769), against the
owner's 2026-07-27 motor-control ruling quoted in knob.js.

### 2.4 Disclosure ("more")

Six mechanisms: the Simple|Advanced **tab**; the rule primitive's **level
select + "more"**; **popovers** (Create, Rules, Timers); **inline toggles**
(Edit → voice editor, kit pool, groove pool, Help me start tree 361, Add
track, Osc 2, Blocks swap); **select-driven reveal** (Custom… metre,
Custom structure); **hover-only** lane tools (9346). And the "Rules show"
level lives on the Advanced tab (741) while it governs rules inside the
voice editors further down — the control is far from what it changes.

## 3. Surfaces that break nested progressive complexity

Ranked by how much a beginner who has only learnt Simple would be confused.

1. **Create popover (279-419).** The second main door (orange, tour step 6)
   opens onto ~29 controls in nine rows, six text/target pairs, and two
   separate "start from nothing" ideas (Blank slate and five Zero buttons).
   Nothing is basic; every entry route is shown at once. Already in TODO.md
   line 35.
2. **Voice editor (12085-12671).** Edit is the one door into a track, and it
   shows 50-70 controls with no layers: rule primitive, randomise row, feel
   row, sequencer, arp, patch dials, save, finder, reset. The reset that
   rescues a ruined sound is the *last* thing in the panel.
3. **Advanced tab as a whole (726-974).** ~65-70 controls on one scroll, mixing
   sound, composition and file operations; the step from Simple's 16 to this
   is a cliff, not a ladder.
4. **Factory presets have no way back.** The Simple tab's whole promise
   ("load one and change anything") lacks the step that makes it safe: after
   turning dials there is no "· edited" and no ↺ Back to factory, because
   loading a preset clears the genre and the mark keys on genre (14261). His
   goal (E) "a good-sounding preset is always one step away" is met for
   genres and voices but not for the twelve presets a beginner actually sees.
5. **Genre rules popover (529-593).** 11 sections fully expanded, ~60-90
   controls, the only Apply-model surface besides one dialog. It *does* use
   knobs and tap-grids well; what it lacks is the rule primitive's layering.
6. **Nuance by non-standard route** (each is small, together they teach that
   there is no single way to drill down):
   - per-track Swing/Density exist only after setting a radio on a
     different tab (7534);
   - favourites only via an option inside the genre select (16597);
   - voice Pool via a select option *or* the rule's Pool button (4361, 6511);
   - undo only by keyboard (16924);
   - the rule "·" mark explained only in a native `title`;
   - lessons only via the engine chip inside an editor (12232);
   - lane tools only on hover (9346);
   - pitch pin only by the P key or Alt-drag (9057, 8905).
7. **Your presets (932-972).** Blank slate duplicated from Create, three
   hint paragraphs, submit terms; this is the "saved layouts" pro feature
   buried at the bottom of Advanced with no keybinding.

Pro layer status: there are **no** keybindings for presets, favourites,
genres or tabs; favourites exist only for genres; there are no pins or saved
layouts beyond whole-setup presets (F in the sequencer/rules inventory).

## 4. Proposed single interaction model

Built from what already works. No new design language; each paragraph names
the existing part that is the template.

**Value control — the knob.** Every continuous or stepped-numeric value is a
knob.js dial: drag up/down for the value, left/right for a span, click the
readout to type, Backspace/Delete to reset. Native range sliders survive only
as the knob-failed fallback. Weights in pools are knobs (or, where a row of
them must stay compact, one number input everywhere at one scale, 1-10, as
the voice Pool already uses). Reset on the pointer is double-click to the
declared default — the owner's current ruling (knob.js 1422-1430) — and the
hub tap's "zero" is documented as such; the header comment and tour must say
the same thing the code does.

**Choice control — the select, with Edited / User / Stock headings.** One of
N is a native select, as the owner chose for pickers (TODO 44). Binary or
three-way *modes* that are always visible may stay segmented radios, but one
value never has two widgets (the lamp and the editor radios). Actions do not
live inside selects; where a list needs "Favourites…", "Pool…" or "Custom…",
it is a small button beside the select (as Rules sits beside the genre
picker). Every picker of saved things uses the same three headings: Edited,
User, Stock — genres and presets included.

**Disclosure ladder — the rule primitive, generalised.** Four rungs, the
same everywhere: (1) the Simple tab; (2) the Advanced tab, whose sections are
collapsed rows showing only Now; (3) "more" on a row opens its next layer in
place (rule-control.js's button, already shipped); (4) Edit / Pool… / Rules
open a panel for the full detail. The "Rules show" level is the global
setting for rung 3 and should move to where it is used, or be mirrored there.
No hover-only and no select-option-only routes to a nuance.

**Reset / back to factory — ↺ Back to factory, beside the name.** The v0.0.206
pattern (genre 491, track row 4514) is the template: a "· edited" mark on the
thing's name, a ↺ button beside it, `confirmBackToFactory` past two changes.
It applies at every level — dial (double-click / Backspace), voice, track,
genre, **factory preset**, rule set — and every reset button uses that label
and sits at the top of its panel, next to the name. Undo gets one visible
affordance (⌘Z already exists; the transport status line can offer "Undo").

**Help — ⓘ for paragraphs, tooltip for a sentence.** The owner set it at 284:
buttons not paragraphs, instructions in the ⓘ. A visible `.hint` line is kept
only for state that changes (dial-confirm, the patch in words, errors, empty
pools). Native `title` is replaced by `describe()` so there is one tooltip
look. The tour and the ⓘs describe the same model the code implements.

**Popovers vs panels — `setupPopover` for tools, inline for editors.** An
occasional tool hangs off an icon or button via `setupPopover` (toggle, Esc,
outside click, focus return). A thing's editor opens inline beneath it
(the voice editor pattern). A modal fixed dialog is used only to confirm a
destructive step. Every surface closes with Esc. Everything commits live; the
two exceptions (Genre rules Apply, voice Pool Done) either become live with
↺ Back as the safety net, or say plainly that they wait for Apply.
